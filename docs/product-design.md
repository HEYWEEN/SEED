# SEED 产品设计

## 用户任务

开发者打开一条长讨论时，需要先知道参与者在评价哪些工程对象、各自持什么态度，再回到原文判断这些评价是否值得跟进。SEED 将每条评价呈现为一张卡片，保留 **Sentiment**（评价方向）、**Opinion**（评价用语）、**Aspect**（被评价对象）和 **Evidence**（原始句子及位置）。

V1 的入口是 Chrome 中 GitHub Issue 网页右下角的 SEED 悬浮球。面板读取该 Issue 的标题、正文和已加载的评论，以正文和评论作为分析输入。首版用公开、英文 Issue 验收，与现有 SESAME 英文流程对接。面板显示实际分析范围，例如「Issue 正文和 12 条已加载评论」。出现加载不全或服务限额时，具体标出范围。

## 面板交互

悬浮球采用 B 款双瓣种子和低饱和墨绿色。点击后直接显示三项操作，再次点击或按 Esc 收起面板并保留结果，点击关闭清除面板状态。 [悬浮球形象对照图](design/seed-floating-button-concepts.png)

| 操作 | 面板行为 |
| --- | --- |
| 提取评价 | 读取当前页面的正文和已加载评论，只运行本机 SESAME。按实际进度显示分句、分类、SHAP、Opinion 和 Aspect 阶段。 |
| 生成摘要 | 展开「基于评价生成」和「直接全文生成」。第一种需要本页有已完成且非空的评价结果，第二种直接使用本页已加载的标题、正文和评论。 |
| 设置 Key | 显示本机保存状态。点击进入扩展独立设置页，可保存、替换或清除 Key。 |

重新打开面板时，按本页已加载内容查找本机缓存，恢复匹配的评价及最近一份摘要。面板会标出「本机缓存」。

评价区按卡片计算正负面数量和比例，并展示 Aspect、Opinion、原句和来源编号。卡片按讨论顺序排列，Aspect 无法确认时显示「评价对象待确认」。提取和摘要独立显示错误与结果，摘要失败时可以继续查看已提取的卡片。

两种摘要模式均生成 1–2 句话，并带可点击的证据编号。全文模式的编号指向消息，评价模式的编号指向被引用原句所在的消息。

## 原文定位

评价卡片和摘要的证据编号可滚动到对应的 Issue 正文或评论。卡片内保留原句、Aspect 和 Opinion，网页内的句子与片段高亮留在下一阶段。

## 数据去向

打开面板查询缓存时只发送内容指纹给本机后端。点击「提取评价」会提交讨论文本，未命中时运行 SESAME。摘要选项在按钮上说明发送内容，用户点击所选模式且没有匹配的本机结果时，DeepSeek 收到结构化评价及对应原句，或当前页面已加载的标题、正文及评论。全文模式保留已加载的代码块。私有或可见性未知的讨论也通过可见的数据去向和明确的摘要点击处理。

## 版本规划

| 版本 | 能力 |
| --- | --- |
| V1.0 | Chrome GitHub Issue 内提取 Sentiment、Opinion 与 Aspect，生成带证据的摘要，并回到原文。 |
| V2.0 | 从其他消息恢复上下文中的评价对象。 |
| V3.0 | 恢复评价之间的关系，组织成讨论簇。 |
| V4.0 | 按工程议题呈现结构化讨论摘要。 |

GitHub Pull Request、GitLab Issue 和 Stack Overflow 属于后续平台适配。
