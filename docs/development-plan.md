# SEED V1 开发计划

第一个可验收切片是一条公开英文 Issue 内的真实链路。用户按下「提取评价」，SESAME 产生至少一条可在原页面核对的评价，之后再补齐摘要与异常状态。

## 实现顺序

| 阶段 | 预计工作量 | 阶段验收 |
| --- | --- | --- |
| 1. 悬浮球与面板 | 0.5–1 天 | 在 Chrome 加载本地扩展后，只在支持的 GitHub Issue 页面显示入口。面板具备打开、最小化、关闭和初始状态。点击「设置 Key」可以在扩展设置页保存、替换和清除本机配置。 |
| 2. 网页采集与分句 | 0.5 天 | 从一条真实 Issue 读取正文和评论，检查消息顺序、来源链接及句子边界。验证两条评论里的相同句子能映射回各自的消息。 |
| 3. SESAME 后端 | 1 天 | 使用真实英文权重完成一次分类、SHAP 和 Opinion / Aspect 提取，面板收到实际阶段和带来源 ID 的结果，并能从卡片打开原评论。 |
| 4. DeepSeek 摘要 | 0.5 天 | 验证两种摘要输入独立工作。评价模式要求有本页已完成的评价，全文模式可直接调用。摘要失败时仍能查看评价卡片。 |
| 5. 原文定位与高亮 | 1 天 | 在真实页面点击卡片，滚动到正确评论并高亮原句及已对齐的 Opinion、Aspect。评论不可用时可打开原链接。 |
| 6. 联调与界面优化 | 1–2 天 | 完成下方验收，补充实际的本地运行说明。 |

合计约 **4.5–6 天**，前提是 SESAME 权重、Python 与 Java 环境可用。开工时先用两三条公开 Issue 试跑真实模型，计时分类、SHAP 和句法提取。若 SHAP 随候选句增加而明显拖慢，再据实测决定输入限额或筛选规则，并检查被跳过的句子里是否有清晰的评价。

扩展代码在 `extension/`，本机服务在 `backend/`。采集与偏移回归用例随对应功能放入 `tests/fixtures/`。

## 首版验收

- **采集范围**。打开支持页面，核对正文、至少两条已加载评论、作者、来源和次序。确认界面展示实际范围，并验证未点击分析时网络请求中没有讨论内容。
- **真实提取**。在几条包含明确正面、负面和中性叙述的公开 Issue 上运行真实模型。人工抽查评价对象、意见和原句，记录错例以及对应的模型、权重和配置。
- **定位**。验证重复句、emoji、链接或横跨多个文本节点的短语。用代码检查结果区间切取的文本和卡片内容逐字一致。对编辑或未加载的评论检查链接回退。
- **摘要**。逐句打开证据核对对象、极性和具体判断。验证关闭摘要时跳过 DeepSeek 请求，遇到超时或无效引用时仍能查看卡片。
- **状态**。验证空页面、无评价、后端不可用、快速重复点击和切换 Issue。观察进度与后端真实阶段一致，旧任务结果和高亮不会出现在新页面。
- **性能**。在记录硬件和配置的同一台机器上，用短、中、长 Issue 记录端到端及各阶段耗时、分析句数和实际 SHAP 句数。

## GitHub 发布准备

首个演示版通过 Chrome 本地加载扩展与本地后端运行。公开发布前，确认 SEED 的许可证和 SESAME 代码、模型权重及第三方资源的可分发范围，补充可复现的安装与资源配置说明。提交仓库的示例使用允许公开的讨论或明确标注的界面用例。
